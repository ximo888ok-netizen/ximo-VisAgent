# PRD：本地应用锚定型长任务 / 长期任务（Long-Task）

> 由产品经理产出。命名说明：本文件为 `.devteam/01-longtask-prd.md`（与既有 `01-prd` 命名空间隔离，总管可按此路径发现）。
> 用户已拍板事项直接写入为**约束**（标 📌），未确认的技术细节进「开放问题」🔴，不替工程师做选型。

## 0. 需求原文与已拍板约束

用户原话：
- 「让用户指定本地某个软件，交给 Agent 执行长任务或长期任务」
- 「在 Agent 输入框加一个本地软件选择按钮，选中后软件直接出现在输入内容中，显示小图标和名称」

📌 用户拍板（不得改动）：
1. **A（单次连续长任务，小时级）与 B（跨天/周期长期任务）都要，先 A 后 B 分期交付。**
2. **输入框选择器：选中后以「图标+名称」chip 内嵌进任务输入内容**，不是独立下拉表单。
3. 架构倾向（总管已给，PRD 按此描述行为）：应用锚定=上下文锚定+前台看门狗（不做硬沙箱）；断点落盘不落屏；完成条件三闸取代单一 60 步上限；预授权作用域包；B=cron 触发+增量+续读断点（不做不眠 Agent）；后台化执行为 P2 加分项。

## 1. 概述

- **一句话目标**：让用户在输入框点一下选中本地某个软件，Agent 就以该软件为「工作现场」，替用户执行小时级连续长任务（A）或跨天周期长期任务（B），全程可暂停、可断点恢复、只在越权时打断用户。
- **目标用户（真实办公画像）**：
  - **财务·小周**：在 ERP/金蝶/用友 + Excel 之间做批量处理——逐张核对发票、录入凭证、导出月报。单次操作重复上百轮，每轮 6-10 个界面动作，人做半天，容易抄错数。
  - **运营·小陈**：每天早上 9 点在 Excel/浏览器后台里拉数、清洗、贴日报；每周一额外做周报。任务天天类似，靠人已连续做了几个月。
  - 共同痛点：软件界面会弹窗、会变布局，脚本/RPA 一改就断；纯 Agent 短任务又受 30 分钟/60 步限制，跑不完一整个月的发票。
- **核心使用场景**：
  - A：小周选中「金蝶KIS」，输入「把这个月发票夹里的 30 张发票逐张录入凭证并核对金额，录完后导出对账表」。Agent 连续跑 1-4 小时；小周切去回微信，Agent 发现离开金蝶自动暂停并通知；回来点金蝶窗口，Agent 从第 17 张续跑；中途断电重启，Agent 读已录入凭证文件核对后从第 17 张继续，不重录。
  - B：小陈把「每日拉数生成日报」注册为长期任务（cron 每天 9:00）。每天到点 Agent 跑一个增量批次（比如 200 行），把进度写断点文件；明天从断点续跑；干完自动停。
- **成功的定义**（可衡量）：
  - A：选定应用后的连续任务（目标步数 ≥150 步或 ≥60 分钟）**完成率 ≥ 70%**；崩溃/重启后断点恢复**不重复已完成副作用**（对账类可验证）；每任务人工审批打断次数相对现状（L2 上限 20 次内逐次弹）显著下降——作用域内操作**零打断**。
  - B：周期任务连续 7 天无人值守准点触发、进度单调前进、失败可追溯。
  - 选择器本身：从点击按钮到 chip 出现在输入框 ≤3 次交互（点击→搜索/点选，选中即完成）。

## 3. 用户流程

### 3.1 主流程（A 期·单次长任务）

1. 用户在输入框左下角点「⊞ 选择应用」按钮
2. 弹出列表面板：搜索框 + 最近使用分组 + 推荐（当前前台窗口置顶）+ 全量已安装列表（图标+名称）
3. 用户搜索/点选一个应用 → 面板收起 → 输入框内容头部出现 chip `[🅴 Excel]`
4. 用户继续输入任务描述，Enter 发送
5. chip 即 targetApp 绑定：随 goal 一起提交（StartTask 扩展 targetApp{exePath,name,icon}），Agent 若发现应用未开则经 `openAppSafe(exePath)` 启动并等窗口（open-app-safe.ts:105-110,145）
6. 用户弹出「长任务授权」卡片：确认 目标应用+目录白名单+允许的 L2 操作类别+敏感排除项，一次性批准 → 任务起跑
7. 运行中：Agent 周期性把进度检查点写盘（工作区文件/SQLite）；离开目标应用超 N 秒 → 自动 PAUSEED + 系统通知；回到目标应用前台 → 提示续跑（或自动续跑，看 N/恢复策略，Q8）
8. 收口三闸：验收断言全过 → COMPLETED；预算（时长/token/步数）耗尽 → 带「预算耗尽」终态+断点保留；停滞（EfficiencyGuard 病理判定）→ 预警后强制收尾或止损
9. 崩溃/重启后：应用启动时扫描未完成的锚定任务 → 展示「上次进行到第 X 项（读自真实工件核对）」→ 一键续跑

### 3.2 主流程（B 期·周期长期任务）

1. A 流程跑通一次「增量型」任务后，用户在完成卡片点「转为长期任务」→ 预填 cron 编辑面板（复用 scheduler.create）
2. 每次到点：读断点 → 跑一个增量批次 → 写断点 → 正常收口；单次增量仍是普通任务（继承单并发队列）
3. 错过的触发（关机）：下次启动/到点合并为一次补跑，不堆积（Q8 定细节）
4. 无人值守审批：命中任务绑定的预授权作用域包 → 自动放行并留痕 decidedBy:'preauth'；超范围 → 挂起+通知，不静默执行

### 3.3 分支 / 异常

| 场景 | 行为 |
|---|---|
| 选中的应用未安装/exe 已被卸载 | 启动前 existsSync 校验失败 → 任务不起跑，输入框报错「目标应用不存在，请重选」，chip 标红保留供重选 |
| 任务中目标应用被用户/崩溃关闭 | 看门狗等价于「离开前台」→ 暂停+通知「目标应用已关闭」，断点保留；用户重开应用后续跑；24h 内可续跑（沿用 autoresume 窗口，orchestrator-autoresume.ts:9） |
| 图标取不到（无 icon 资源/提取失败） | chip 与选择器列表回退为「名称首字圆形字母图标」，功能不受阻 |
| 第二个 chip 冲突 | **禁止多选**：已有 chip 时再选新应用 = 直接替换并 toast 提示；任何时刻至多 1 个 chip |
| 岛窗口不可见（B3） | 预授权命中同样放行（放行依据是启动时显式 ack 的作用域包，不是档位巧合）；超范围操作挂起+系统通知（不静默）。此条是 B1/B3 刹车的**显式设计修正**，见 Q6 |
| 周期任务到点时上一轮仍在跑 | 跳过本轮，job.lastStatus 记「跳过：前任务未完」；不并发（编排器并发恒 1，autoresume.ts:21 注释） |
| 断点文件与真实工件不一致（工件被用户手改/删） | 恢复时以真实工件为准：逐条对账 mission_artifacts 的 contentHash/stale，不一致项重做并在续跑预览中列出 |
| 任务从未授权应用窗口产生跨应用操作（如弹浏览器下载） | 作用域包外应用 → 实时审批弹窗（保持现状语义），用户拒绝则 Agent 绕行或问用户 |
| 目标应用多窗口 | 看门狗以「目标进程任一窗口在前台」为准，不按单 hwnd 判定 |

## 5. 页面与信息结构

- **授权卡（PreAuthDialog）**：作用域包四节（应用/目录/操作类别/敏感排除），逐项展示默认勾选，底部风险确认按钮（复用 autonomous ack 模式，approval-policy.ts:70-77 的 ack 强校验思路）。
- **运行中控制条（扩展）**：锚定标识、进度 x/y、暂停原因横幅、续跑按钮。

## 6. 不做范围（Out of Scope）

- **硬沙箱/系统级隔离**（禁止应用联网、进程级权限裁剪）—— 架构倾向 1 已否决：锚定=上下文+看门狗，安全靠作用域包审批。
- **多屏/多显示器编排** —— 无用户诉求，感知链路现按主屏（host-capabilities.ts:20-27）。
- **不眠 Agent（常驻后台无限跑的单体进程）** —— 拍板 5：B=到点触发+增量+断点，崩溃域内解决。
- **多应用协同 / 多个 chip 同时绑定** —— 禁止多选是红线。
- **全局快捷键唤起选择器** —— 用户只要求在输入框加按钮。
- **不可逆操作自动回滚**（Agent 代录凭证的撤销需人工在应用内完成）—— 超出现有审计能力，敏感排除清单负责事前防呆。
- **改动单并发模型**（orchestrator 并发恒 1 保留）。
- **非 Windows 平台**（UIA/侧车/注册表均为 Windows 特定）。
