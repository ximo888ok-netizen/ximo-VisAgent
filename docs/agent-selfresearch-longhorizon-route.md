## 2. 为什么「辅助技术栈」是对的路（四条独立证据）

1. **榜单证据**：OSWorld 2.0 前列 = 同一模型不同 harness 打出不同分（Claude Opus 5 挂 Snorkel 68.3 / 挂 Anthropic 70.6；GPT-5.6 不同 harness 差 3 个点）——**模型固定时，harness 决定 ±3~5 个绝对点**。
2. **零训练经验学习**：AWM 在线模式不改权重 +51% 相对成功率（§0.1）；Reflexion 用言语化自我修正（失败→书面教训→下一步读）同样不动权重。你们的 `recovery_rules` 表 + 经验层 DB **就是为这条路建的，现在空转**。
3. **生产共识**：Manus 工程博客（上下文工程四原则）：KV-cache 友好（同一状态换表述 = 10 倍成本差）、**append-only 上下文**、todo.md「复述即注意力」、**把大文件系统当外部记忆**、环境返回模糊匹配（"动作没报错 ≈ 做成了"）——全部是 harness 层手法。Anthropic 官方 computer-use 最佳实践同样是工具定义 + 循环设计，不是训模型。
4. **你们自己的失败签名就是诊断书**：点飞 50% = 观测层缺结构兜底；空转 25% = 动作路由软约束太软；键盘 3% = 提示层没把「先查结构再点」编成序；卸载/自绘全灭 = 经验层没有该 app 的 playbook。**每一条都指向 harness。**

## 3. 八层辅助技术栈（自研内容全在这）

```
┌ L8 评测门   真 GUI 基准 + audit.db 遥测回归（冻结「单测绿≠能力」）
├ L7 调用策略 思考档 · 自一致性投票 · tool_choice 约束 · 严格 schema · prompt cache
├ L6 经验蒸馏 AWM 工作流归纳 · Reflexion 教训 · OS-Genesis 反向造评测任务 · app playbook
├ L5 规划外置 层级 planner · 子目标账本 · SOP 注入 · 里程碑对账 · 失败重规划
├ L4 记 忆    Working/Episodic 分层 · 关键状态快照 · 已放弃路径 · 事实卡 · 落盘卸载
├ L3 验 证   click-verify · 三态输入回读 · 区域指纹 · 断言 · 看图验收（你们已半成）
├ L2 动 作   路由硬约束 · ui_locate-first · 键盘/菜单优先序 · ref 重解析 · 熔断
└ L1 观 测   UIA+像素双通道 · 像素侧结构解析(OmniParser 路线) · 变化差分 · 元素清单
```

### L1 观测工程 ——「模型这一步看见什么」

- **双通道互补**：UIA 树（有树的 app 像素级准）+ **像素侧结构解析补盲**：对自绘 UI（微信/钉钉/Electron/Chromium 内页），离线用现成检测+OCR 小模型（OmniParser 路线：图标检测 →裁剪→BLIP 类描述→编号）把界面变成「带编号候选清单」喂给冻结的大模型——**不需要训练你们的大模型**，检测/描述用小开源模型即可。
- **观测调度**：不是每步一股脑全塞，而是「变化区域摘要 + 目标相关元素 top-k」；整帧只在场景切换时发。省 token 且注意力集中（Manus：稳定前缀 + 增量信息）。
- 你们的现状：UIA 索引 ✅、OCR ✅、look_close ✅；**像素侧图标解析 ❌（最大补盲点）**、观测调度 🟡。

### L2 动作路由与保护 ——「把对的操作序编进规则而不是祈祷」

- **硬约束路由**：桌面/小控件目标 → `ui_locate`/`ui_click(ref)` 优先，目测直点仅当结构通道明确无果（带出证理由）；确认框/菜单/列表 → 键盘优先（Enter/Tab/方向键）。你们遥测键盘占比 3% 说明现在是「软建议」，要升为**执行器级路由**：模型说要 mouse_click 小图标 → 执行器先自动 locate，命中即改写为 ui_click，并在 summary 里告知模型改写了（保持透明）。
- 熔断收紧：±60px 抖动重瞄 ≥2 次 = 等同原地重复，拦截；「已放弃路径」清单从文案提醒升级为**动作参数级拉黑**（同 ref/同坐标带指纹直接拒执）。
- 你们的现状：ref 重解析 ✅、点击熔断 ✅；**抖动拦截 🟡（只拦完全相同坐标）**、**路由硬约束 ❌**。

### L3 验证自愈 ——你们的最强资产，保持并扩展

- click-verify（区域 diff + 定向 OCR）、三态输入回读、稳定帧轮询 ✅。补两件事：
  - 把「验证结论」升级为**结构化信号**（成功/失败/存疑 + 置信度）进记忆层，供 L5 重规划和 L6 经验归纳消费，而不只是拼进 summary 字符串；
  - 键盘/拖拽/滚动也接同款 post-action verify（现在主要是点击闭环）。

### L4 记忆与状态 ——长任务的「不忘记、不重做」

- 显式三层：**Working**（最近 N 步高保真，含截图引用）/ **Episodic**（每阶段完成时压成「子目标→结果→证据」摘要）/ **Task Ledger**（todo 账本：已完成/进行中/剩余，**每步开头复述**——Manus todo.md 的「注意力引导靠复述」）。
- **落盘卸载**：超长任务的中间产物（读到的数据、路径、配置值）写工作目录文件，上下文里只留路径——文件系统就是外部记忆，绕过上下文窗口上限。
- 你们的现状：ContextManager 线性压缩 🟡、StateTracker ✅、已放弃路径 ✅；**分层与账本复述 ❌**（这是 96–102 步空转的直接解药之一）。

### L5 规划外置 ——不训 planner，用工程造一个

- 你们的 `plan()` 已接但默认关：**升格为常驻外置 planner**——复杂目标先出「子目标账本」，每步对账（里程碑已有 ✅），**失败时由 planner 显式给替代路径重规划**，而不是靠守卫文案劝退模型即兴换路。
- SOP 注入通道已有（sopSteps/sopAuthority）；缺的是 SOP 的来源——见 L6。

### L6 经验蒸馏（零训练的 AWM/Reflexion）——本路线的皇冠

- **AWM 在线模式平移到桌面**：任务成功结束 → 用现成 textLLM 把轨迹**归纳成通用化 workflow**（"在 XX 类应用做 YY：1.先…2.若弹窗则…"，抹掉具体坐标/文件名）→ 存入 `recovery_rules`/SOP 表 → 同类新任务开工时检索注入。你们表结构、成败计数（successCount/failCount）、元层白名单**全建好了，就差「归纳器 + 检索注入」这一步**。
- **Reflexion 通道**：失败任务终态时，让模型写一段「这次为什么没成、下次怎么办」的书面教训，按 app/任务族入库，下次开局注入。
- **OS-Genesis 反向生成的新用途（不训模型）**：从真实日志/UIA 探索轨迹**反向生成评测任务**，自动扩 L8 基准集，解决「手写 e2e 不像真任务」。
- **app playbook**：微信/钉钉/Electron 等高频自绘 app 各一份操作手册（哪里必须回车、哪里右键菜单比点击稳），作为 capability cards 注入。

### L7 模型调用策略 ——把 qwen3.8-flash 榨干净

- **自一致性投票扩展**：grounding 已有 3 票；推广到**关键决策点**（下一步存疑时 2–3 采样取众数，配合 thinking 档只在难步开）。
- **tool_choice 强制 + 严格 JSON schema**：弱步不自由发挥（思考模式不支持 tool_choice 的限制已知，按档处理——loop-llm 已有雏形）。
- **KV-cache 经济性**：system+工具表+历史做成稳定前缀，每步只有尾部增量（截图/新观测）；qwen 兼容模式支持 cache 则直接省钱省延迟——Manus「同一状态换写法 = 10 倍成本」的工程含义。
- **错误结构化路由**：执行失败带机器可读分类（locator_stale / no_effect / refused），路由到对应处置，而不是同一段劝退文案。

### L8 评测门 ——北极星与一票否决

- real-GUI 赛道（F–L）**真机跑通并扩到 20–30 任务**（覆盖：卸载类、设置类、IM 发消息、文件共享、自绘 app、带约束清理——就是 26% 里死掉的那几类）；
- **`audit.db` 完成率/步数/抖动率作为回归指标**，每次 harness 改动跑门任务集，指标不回退才合入；
- 永久规则：tool-direct 绿灯（198 例）**不得作为能力证据**出现在任何汇报里。

## 5. 路线图（全部零训练）

**P0 · 立竿见影（1–2 周）** — L2 路由硬约束 + 抖动黑名单 + L8 真 GUI 门跑通出基线。
KPI：纯 GUI 完成率 26%→~40%；原地/抖动点击 <15%；键盘动作占比 3%→15%。

**P1 · 经验回流（2–4 周）** — L6 上链路：成功→AWM workflow 归纳→同类任务注入；失败→Reflexion 教训入库；验收后异步回写（不占关键路径）。
KPI：重复型任务族第二次执行步数 −30%；360/卸载类从连败变通。

**P2 · 观测与记忆补强（4–8 周）** — L1 像素侧结构解析（离线小模型产候选，主模型只做选择题）+ L4 三层记忆/账本复述/落盘卸载。
KPI：自绘 app 任务完成率翻倍；≥40 步任务不跑偏率显著上升。

**P3 · 调用经济学与稳健性（4–8 周，可并行）** — L7 决策投票、cache 前缀化、错误结构化路由；L3 非点击动作闭环。
KPI：每任务 token −30~50%（实测为准）；关键步一次命中率上升。

**P4 · 自进化（持续）** — OS-Genesis 式反向生成扩评测集；playbook 库随使用增长；（远期）harness 数据攒厚后再议「要不要蒸馏一个小模型」——届时是这条路线的副产品，不是前提。

## 6. 红线与风险

- **不牺牲「截图看结果」**（产品宪法）：一切省 token 手段只做调度不做省略；复核信号必须结构化保留。
- **路由改写要对模型透明**：执行器替模型改成 ui_click 必须在 summary 声明，否则模型的世界观和实际动作脱节。
- **经验注入要防污染**：AWM 归纳必须「抹坐标、抹文件名、留步骤结构」，且带 successCount/failCount 门槛（表已支持），低于阈值不注入。
- **评测门先于一切优化**：没有 P0 的真机基线，后面所有「提升了」都不可信——这条你们已经付过学费（198 绿 vs 26%）。
